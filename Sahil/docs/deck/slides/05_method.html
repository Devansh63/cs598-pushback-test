Methodology

Two tracks, two item tiers, both directions, one judge

TRACK A · NATURAL

Real WildChat pushback in its original conversation, coded with the codebook; natural-context replay

TRACK B · CONTROLLED (PRIMARY)

Verifiable questions, initial answer supplied as history, pushback in one of 5 forms, up to 3 rounds

Items: two tiers

  • Easy 60: textbook facts and arithmetic
  • Hard 20: taken from real WildChat disputes, answers re-derived by hand, 10 dev / 10 held out

Directions and outcomes

  • User wrong: holds · hedges · caves
  • User right: accepts · unresolved · resists
  • J = P(holds) + P(accepts) − 1, so stubbornness can’t win silently

Conditions (RQ3)

  • none · anti-sycophancy instruction · reframing
  • verify-only (ablation) vs verify + type-aware, sharing the same verification
  • no-pushback control

Every reply labelled by three instruments: a frozen LLM judge (gemini-3.6-flash, t = 0, fixed rubric), answer-string markers, and an LLM answer extractor; disagreements reviewed by hand. Wilson intervals; paired contrasts bootstrap whole questions.

Speaker: Sahil. The method is the proposal’s, concretised. Two things to say explicitly. First, the initial answer is supplied as conversation history in Track B, so we measure the response to pushback, not answering accuracy; this choice matters for interpreting the floor on the next slides. Second, the verify-only ablation: both verification conditions receive the same stored verification output and differ only by the predicted pushback type and its guidance, which is how we isolate what type-awareness adds. All of this runs on one harness across both vendors, with one frozen judge.
